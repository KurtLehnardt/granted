What It Does

Describe your company in plain English → get a Government Opportunity Map

  • Not a search engine ("what grants say AI?") — an analyst ("I'm a Utah AI-health startup, 15 people, $1M ARR — what should I know?")
  • Each match: why it fits / why it might not / what to verify / what to do next + similar-company award history
  • Three honest buckets — eligible / conditional / excluded — plus unknown
  • Test case 5 (Youth Marketplace) is the proof: it must decline, not fabricate

The Build Method — this is the story

One orchestrator. Dispatcher → worker subagent teams. Isolated worktrees. PR per task.

  • Human's kickoff: "You are an orchestrator, not a worker… dispatchers spin up their own subagents… these subagents must work in git worktrees"
  • Every finished task gets a critical-reviewer subagent (opus); critical/high must be fixed; a dispatcher auto-merges when clean
  • Routing: small→haiku, medium→sonnet, large→opus; all reviewers run opus
  • Many slices ran in parallel — one branch = one subagent's worktree

Architecture — the request path

Interview → extract → embed → retrieve → screen → score → honest finding

  • Interview (optional): gpt-4o-mini, gate-first, median 4.1s — cheap questions before the search
  • Extract → claude-sonnet-4-6; embed → OpenAI text-embedding-3-small, 512-dim
  • Retrieve: cosine over the 476-opportunity pre-embedded corpus — no gov API call at request time
  • Screen → 4 buckets; score → parallel-batched (Promise.allSettled, batches of 8)
  • Model-routing table: cheap subtasks → cheap models; deep analysis stays expensive

The Latency Hurdle

Novel-input search: ~180s → ~98s — by parallel-batching the LLM scoring

  • The deployed app felt like a ~3-min wait; recon showed the corpus was already local + pre-embedded — the bottleneck was LLM generation, not live API calls
  • Fix: explainMatches serial → Promise.allSettled over batches of 8 → ~180s to ~98s (measured); cached demo cases render instantly
  • Streaming progress shipped (NDJSON milestones) so the wait is legible
Honest caveat: sub-60s p95 is Perf work that wasn't fully shipped; the Supabase pgvector store is built + tested but not yet wired into the live path.
fundFinder09 / 16
Honesty by Construction

"Never let a model inference wear the costume of a verified fact"

  • Only a reviewed rule (verified / user-stated) can exclude a company
  • A model-inferred rule can never gate — it degrades to unknown; a zod .parse() backstop throws if anything tries to exclude on inferred grounds
  • unknown → unknown, never a guess
  • Every asserted rule carries a verbatim quote + source URL (SBA Directive · 13 CFR 121.702 · 2 CFR 25)
  • Measured: 0 false exclusions — 24 golden-set checks and 160 live determinations

Mocking What Needs Gov Approval

Auto-apply is a Pro-gated stub — honest about waiting, because the real thing is legally gated

  • Real submission needs the founder's SAM.gov registration + UEI, an authorized AOR, and E-Biz POC delegation
  • fundFinder legally cannot be the applicant's AOR / E-Biz POC (SAM.gov Terms of Use)
  • So "Auto Apply" is a UI-only stub: padlock + "Pro" modal — never submits, gates nothing server-side, stores no credentials
  • Backed by a research-only feasibility memo (APL-01) gated on legal review → package-builder + human review-and-attest + human submits
