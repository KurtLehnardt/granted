A federal-funding tool built almost entirely by delegating to AI agents. The interesting part isn't the code. It's how much of a single 8-hour build we spent not writing any.

The premise

We didn't start with code. We started with a spec and a north star.

  • A north star for where the spec is silent: "a personal government-funding intelligence analyst for every startup." It governs every call the spec doesn't make.
  • An orchestrator contract (CLAUDE.md): one agent plans and delegates; it never writes code itself.
  • A 1,210-line specification (the orchestrator prompt): requirements, shared contracts, ship order, acceptance criteria.

    │  ORCHESTRATOR  │  decompose · plan · route · synthesize · MERGE centrally

Cheap dispatchers, expensive workers. Many run in parallel; each gets a clean context. Only the orchestrator controls what reaches main.

Inside the 1,210-line orchestrator prompt

How the work gets delegated

  • Recon before code. First produce an as-built map of the real pipeline, then confirm or kill every [HYPOTHESIS]. Never assign work to fix a problem you haven't proven exists.
  • Contracts first. Shared schemas, flags, and the prompt registry ship before any feature code, or parallel teams produce unmergeable work.
  • Every task is a sealed contract: Context · Files-in-scope · Definition-of-done · Out-of-scope · Test plan · Escalate-if. A task with no "out of scope" isn't ready to assign.
  • Route to specialist teams along a dependency graph: Contracts, Canon, Eligibility, Pipeline, Perf, Intel, Apply, Evals… each owning a file boundary so no two workers touch the same code.
  • Ambiguity is named, never guessed. Log it to open-questions.md, take the lowest-regret default, and record that default in the task.

The heart of it

Hours in — still not writing code.

We had a reasonable feature list: ask better questions, add a progress bar, competitor analysis, auto-apply. We could have started building any of them in the first ten minutes.

Instead we turned the list into a specification, then attacked the specification. Four rounds. Here's what that surfaced.

What the spec surfaced · 1 & 2

The ask was rarely the problem.

the progress bar

wasn't the problem

The search took three minutes. A beautiful bar over three minutes is still three minutes. The spec now requires you to measure where the time actually goes before changing anything. A guess about what's slow is usually wrong. A progress bar only makes the wait feel better; the real fix was to find the slow steps and run them at the same time instead of one after another.

"auto-apply"

became "assisted apply"

Submitting a federal application is a legally attested act. A human certifies it's true. A product that clicks submit for you doesn't save time, it transfers liability to you. So: prepare, prefill, review-and-attest. The human submits. Always.

What the spec surfaced · 3 & 4

The gap that would have sunk it.

the correctness floor

eligibility, first

Nothing in the original list checked whether a company was eligible for the grants we surfaced. Perfect ranking on a list you can't apply to is worse than no list. It costs a founder a week to find out. That became the floor the whole product sits on.

assumptions → hypotheses

confirm before acting

We labeled every assumption about our own codebase as an explicit hypothesis to confirm before anyone acted on it. The fastest way to waste time and tokens is to fix a problem that wasn't verified.

Each addition answered one question: what has to be true for the ask to actually work? A progress bar needs a fast search behind it. A match list is useless if you're not eligible. The paid features need accounts.

The rules that made parallelism safe

How dozens of agents didn't collide

  • Git worktree per task. Many agents edit the same repo without corrupting each other.
  • PR-per-task; the orchestrator merges centrally. One place controls ordering, conflicts, and main.
  • Six gates on every change: typecheck · test · build · hex · contrast · prompts. Green, or it doesn't merge.
  • Feature flags default-OFF. Every capability ships dark; the flag-off path stays byte-identical.
  • Verify the diff, not the report. Agents can over-claim; git is the source of truth.

What makes it different

The honest "no," enforced in code, not just prompts.

The differentiator: most tools always return something. Granted has the integrity to return a calibrated, well-explained nothing, and to say "we don't recommend applying" when that's the truth.

  • Anti-fabrication is a type-system guarantee. A model-inferred exclusion literally cannot render; the schema throws rather than fabricate.
  • Every match is grounded in a real federal award record, with citations.

Validation, on the live path

Your happy path can hide a broken product.

A precomputed demo cache made the flagship look perfect. Underneath, a too-strict boundary check was failing ~2 of every 3 real novel searches with "the search didn't complete."

It surfaced only when we ran the golden set live (31 real searches, real spend), which errored 21/31. Evaluate the live path, on breadth. The same run later validated the discernment layer end-to-end (30/31).

The gotchas we paid for once

What bit, and what it taught

  • The dead-end masked by cache. A strict schema turned completed searches into errors on the live path; only the golden-set run caught it.
  • Over-reported work. An agent claimed to have built features that had no code. Trust, but verify the diff.
  • Credit exhaustion mid-run. A heavy golden-set sweep drained the LLM account and 400'd halfway. Pace real-money runs.
  • A stale working dir. Subagents read an old commit and "saw" the wrong app. Always branch from origin/main.

The through-line

The hard part was never building faster.

It was being willing to cut the features that didn't deserve to exist. Once you've done that, ruthlessly, handing the actual work to a system that runs itself is the easy part.

Spec first. Delegate second. Merge from one place. Put integrity in the code, not just the prompts.
